# 설득력 점검 (전하기 전에)

설득은 상대가 근거를 이해하고 판단할 수 있게 돕는 일이다. 설득에 성공했다고 답이 옳아지지는 않는다. 그래서 이 스킬은 글을 그럴듯하게 다듬지 않는다. 상대가 판단하기 어렵게 만드는 곳, 근거보다 세게 말한 곳, 보는 사람을 잘못 이끄는 곳을 찾는다.

기준은 수사학의 세 요소를 데이터 보고에 옮긴 모델이다: 공감(파토스), 형태(에토스), 논리(로고스). 근거는 `references/`에 있다.

## 먼저 읽는다

- 점검할 결과물: 보고서, 제안서(md, txt, html). 대시보드면 html이나 화면 캡처, 차트면 png와 그 코드
- 결정 정보: 결정권자, 기한, 선택지, 제약. 적어 둔 파일이 있으면 읽고, 없으면 사용자에게 세 가지만 묻는다: 누가, 언제까지, 무엇 중에서 고르나
- 근거 폴더: 분석 노트, 계산 코드, 집계 결과가 있는 폴더. 결과물의 숫자는 여기에 있어야 한다. 어디인지 모르면 묻는다
- 지표 정의(용어집)가 있으면 함께

폴더 예시(이 스킬을 처음 만든 실습 폴더 구조): 결과물 `산출물/5_한장제안.md`, 결정 `산출물/1_결정할일.md`, 근거 `산출물/3_분석노트.md`와 `산출물/코드/`, 정의 `data/용어집.md`. 다른 구조면 위 네 가지에 해당하는 파일을 찾아 쓴다.

## 절차

1. **공감: 누구의 어떤 결정인가.** `references/rubric.md`의 공감 칸으로 본다.
   - 첫 줄(제목)이 결정권자의 결정에서 시작하는가. 분석 주제("9월 매출 분석")가 아니라 요청 문장("개발 3일을 결제 오류 수정에 배정해 주십시오")인가
   - 결정권자의 제약(예산, 일정, 인력)이 근거나 제안에 반영됐는가
   - 흐름이 문제 → 탐색 → 해석 → 제안 순서로 이어지고, 결말(무엇을 해 달라는지)이 있는가
2. **형태: 이 사람에게 맞는 그릇인가.** `references/form_selection.md`의 여섯 문항으로 상대 조직의 데이터 거버넌스와 활용 수준을 매긴다. 모르면 추정하고 추정이라고 적는다. 표에 따라 탐색형(데이터 테이블), 요약형(대시보드), 해석형(인사이트 리포트) 중 맞는 형태를 정하고, 지금 결과물의 형태와 비교한다. 다르면 무엇을 더하거나 빼야 하는지 적는다.
3. **논리: 근거에서 결론까지 가도 되는가.**
   - 문장마다 사실, 해석, 가정, 제안 중 무엇인지 표시하고, 해석이나 가정이 사실처럼 쓰인 문장을 고른다
   - 근거 숫자를 확인한다. `python3 <이 스킬 폴더>/scripts/number_check.py <결과물> <근거 폴더>` 를 돌려, 결과물의 숫자 중 근거 폴더 어디에도 없는 것을 찾는다(표준 라이브러리만 씀). 찾은 숫자는 계산 코드나 출처를 묻는다. 숫자를 새로 지어내지 않는다
   - 대시보드처럼 숫자를 코드가 그리는 화면은 스크립트가 화면 숫자를 읽지 못한다. 그때는 화면 캡처의 숫자를 생성 코드의 집계 결과와 직접 대조한다(파일을 새로 쓰지 않고 돌린다)
   - 숫자마다 기간, 집단, 비교 기준이 붙었는가. 원인을 확정한다고 쓰지 않았는가. 검토했지만 버린 설명과 한계가 있는가
   - 차트와 화면은 `references/cognitive_risks.md`로 본다: 감각(무엇이 먼저 보이나), 이해(무엇과 비교하나), 기억(맥락이 붙었나) 단계와, 인지 위험 여덟 가지(강조 남용, 시각적 편향, 시선 유도 왜곡, 대표성, 가용성, 앵커링, 확증 편향, 다크 패턴)
4. **고칠 것을 고른다.** 찾은 것 중 결정권자의 판단을 가장 크게 흐리는 셋을 고른다. 고르는 순서: 근거에 없는 숫자, 사실처럼 쓴 해석 > 결정과 요청이 없음 > 형태가 안 맞음 > 차트의 왜곡 > 표현. 고칠 문장은 "지금 → 이렇게"로 보여 준다. 고친 글을 통째로 다시 쓰지 않는다. 고칠지는 사람이 정한다.
5. **반론 리허설.** 1단계의 결정권자 역할을 맡아(그의 상황과 제약 그대로) 반론 셋을 던지고 사용자가 답하게 한다. 답이 막히면 문장을 다듬지 말고 분석 노트로 돌아가자고 한다.

## 판단 지점에서 멈춘다

- 상대 조직의 수준을 추정했으면, 형태 판정 전에 그 추정이 맞는지 묻는다
- 근거에 없는 숫자가 나오면 빼거나 고치기 전에 사용자에게 출처를 묻는다
- 결론 자체를 바꿔야 할 것 같으면 그렇다고만 말한다. 결론은 사람이 고른다

## 출력

결과물과 같은 폴더에 `<결과물 이름>_설득점검.md` (실습 폴더 구조면 `산출물/5_설득점검.md`). 틀은 `assets/check_template.md`. 결과물 원본은 고치지 않는다.
