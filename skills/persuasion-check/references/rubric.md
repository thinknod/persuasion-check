# 점검표: 공감, 형태, 논리

항목마다 통과 / 고칠 것 / 해당 없음으로 판정하고, 판정의 근거가 되는 결과물의 줄을 그대로 옮긴다.

## 공감 (파토스): 결정권자가 자기 이야기로 읽는가

이야기의 세 요소를 보고서에 옮긴다. 인물 = 결정권자, 배경 = 그가 처한 상황과 제약, 플롯 = 문제에서 제안까지의 흐름.

| 항목 | 통과 | 고칠 것의 예 |
|---|---|---|
| 인물: 결정권자가 정해져 있다 | 첫 줄이나 머리에 누구의 결정인지 보인다 | 누구에게 내는 글인지 알 수 없다 |
| 인물: 첫 줄이 그의 결정이다 | 제목이 요청 문장이다 ("~해 주십시오", "~를 정해 주십시오") | 제목이 분석 주제다 ("9월 매출 분석", "결제 퍼널 현황") |
| 배경: 제약이 반영됐다 | 예산, 일정, 인력 같은 제약에 맞춘 제안이다 | 제약과 상관없이 "모두 개선" |
| 플롯: 흐름이 있다 | 문제 → 탐색 → 해석 → 제안. 결론은 맨 위에도 한 번 | 배경 설명이 길고 결론이 끝에 묻혀 있다 |
| 플롯: 결말이 있다 | 예, 아니오로 답할 요청과 언제 무엇으로 확인할지 | "참고 바랍니다"로 끝난다 |

## 형태 (에토스): 이 조직에 맞는 그릇인가

`form_selection.md`로 맞는 형태를 정한 뒤 비교한다.

| 항목 | 통과 | 고칠 것의 예 |
|---|---|---|
| 형태가 수준에 맞다 | 활용 수준이 낮은 상대에게 해석형(풀어 쓴 리포트) | 대표에게 원본 표 20줄을 그대로 |
| 정의가 붙어 있다 | 지표 정의, 기간, 출처가 한 줄씩 | "완료율"이 무엇의 비율인지 없다 |
| 신뢰를 주는 단서 | 데이터 출처, 처리(중복 제거 등), 재현할 코드 위치 | 숫자의 출처가 없다 |
| 한 장의 분량 | 핵심 정보 덩어리 일곱 개 이하 | 차트 여섯, 숫자 스무 개 |

## 논리 (로고스): 근거에서 결론까지 가도 되는가

| 항목 | 통과 | 고칠 것의 예 |
|---|---|---|
| 사실, 해석, 가정, 제안이 나뉜다 | 해석은 "~로 보입니다, 가장 강한 설명은", 가정은 "확인하지 않았지만" | "원인은 앱 업데이트다"를 사실처럼 |
| 근거 숫자가 분석에 있다 | number_check.py에서 출처 없는 숫자 0개, 또는 출처를 밝힘 | 노트에 없는 "매출 30% 감소" |
| 숫자에 비교가 붙는다 | 기간, 집단, 비교 기준 (예: "신규, 6월 79% → 9월 61%") | "완료율 61%"만 |
| 원인을 확정하지 않는다 | 다른 설명과 판정이 한 줄 이상 | 다른 설명 없이 한 원인 |
| 한계와 다음 확인이 있다 | 확인 못 한 것, 무엇이 보이면 제안을 바꾸나 | 한계가 없다 |
| 차트가 질문에 답한다 | 차트 제목이 답 한 줄, 비교 대상이 함께 | 제목이 "월별 추이" |
| 인지 위험이 없다 | `cognitive_risks.md` 여덟 가지 모두 통과 | 0에서 시작하지 않는 축으로 차이를 키움 |

## 고칠 것 고르는 순서

1. 근거에 없는 숫자, 사실처럼 쓴 해석 (판단을 틀리게 만든다)
2. 결정과 요청이 없음 (판단할 수 없게 만든다)
3. 형태가 안 맞음 (읽을 수 없게 만든다)
4. 차트의 왜곡 (잘못 보게 만든다)
5. 표현 (늦게 읽히게 만든다)
